🚀 Local Setup

1

Prerequisites

Make sure you have Python 3.11+, Node.js 18+, and the CF CLI installed.

# Verify versions
python3 --version   # 3.11+
node --version      # 18+
cf --version        # CF CLI

# Log in to BTP CF
cf login -a https://api.cf.us10-002.hana.ondemand.com
# Org: presalesbtplac  /  Space: DSA
2

Clone the repositories

git clone https://github.tools.sap/I816087/dh-app-api.git
git clone https://github.tools.sap/I816087/dh-app-ui.git
3

Backend — install & configure

cd dh-app-api
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Create manifest from template, then fill in credentials
cp manifest.template.yml manifest.yml
# Edit manifest.yml — get credential values from Rodrigo via Teams
Never commit manifest.yml. It is gitignored. Share credentials only via Teams or a call — never over email.
4

Backend — run locally

uvicorn main:app --reload --port 8000

# API:  http://127.0.0.1:8000
# Docs: http://127.0.0.1:8000/docs
5

Frontend — install & run

cd dh-app-ui
npm install
npm run dev

# App: http://localhost:5173
# Requires backend running on :8000

# 3. Open a Pull Request on github.tools.sap

☁️ Deploy to BTP

▲

Deploy backend

cd dh-app-api
# manifest.yml must exist with real credentials
cf push dh-api

# Secrets only need to be set once and persist in CF:
cf set-env dh-api DH_DB_PASSWORD "..."
cf set-env dh-api AZURE_CLIENT_SECRET "..."
cf set-env dh-api JWT_SECRET "..."
cf restage dh-api
▲

Deploy frontend

cd dh-app-ui
# .env.production must exist (gitignored — copy from template)
npm run build
cd dist
cf push dh-app

📖 User Guide

The DH SA Main App is accessible at the BTP URL shared by the project owner. Login requires an @sap.com account via Azure SSO — no separate password needed. Click each module below to expand its guide.

🔐
Login & Access Azure SSO · first-time access
▼

How to log in

  • Open the app URL in your browser.
  • Click Sign in with Microsoft.
  • Authenticate with your @sap.com account.
  • On first login your account is created automatically — you will see a limited view until an admin grants your role.

Roles

  • SA (Solution Advisor): access to Pipeline, AE Territory, Melody, and Outreach modules.
  • Admin: all SA access + ETL upload, user management, and permissions panel.
First time? Contact Rodrigo on Teams to have your role assigned before your first session.
📊
Pipeline Dashboard Weekly snapshots · YoY analysis · opportunity list
▼

Overview

Shows the current pipeline snapshot with week-over-week and year-over-year comparison. Data is loaded from the most recent CSV ingested via ETL.

Key features

  • Filters: filter by region, sub-region, AE, solution family, or stage.
  • YoY chart: compares current pipeline ACV vs. the same week in the prior year.
  • Opportunity table: sortable list with account, AE, solution, stage, ACV, and close date.
  • Export: download the filtered view as Excel via the Export button.
Tip: Use the "Week" selector to navigate historical snapshots — useful for trend analysis in QBR prep.
🗺️
AE Territory Analysis Per-AE pipeline · outreach contacts · account solution map
▼

Overview

Provides a territory-level view grouped by AE. For each AE you see their active opportunities, assigned contacts, and solution coverage gaps.

Key features

  • Territory map: AE list with total ACV, number of accounts, and pipeline health indicator.
  • Opportunity drill-down: click any AE to expand their opportunity list with full details.
  • Outreach contacts: for each opportunity, open the Contacts drawer to see assigned contacts, add new ones, and track outreach status.
  • Suggestions: the app suggests contacts based on account and solution, pre-populated from SAP's account data.
  • Account Solution Map: shows which SAP solutions are already in pipeline for an account and highlights coverage gaps with pre-suggested competitors per solution.
Tip: Use the Account Solution Map before an EBC or customer call to identify white-space and prepare competitor talking points.
🎵
Melody Activity Tracking Presales activities · team targets · coverage
▼

Overview

Displays presales activities logged in Melody/Databricks, aligned to team targets. Helps managers track SA engagement across accounts and solutions.

Key features

  • Activity list: filter by SA, solution family, account, or date range.
  • Target progress: shows activities completed vs. target for each SA in the period.
  • Solution breakdown: how activities are distributed across solution families.
Tip: Data is loaded via the ETL module — if figures look stale, ask the admin to re-ingest the latest Melody export.
📤
ETL — Data Ingestion Admin only Upload pipeline, VAT, Melody, targets
▼

Overview

Allows admins to upload CSV/Excel files that populate the app's database. This is how new data reaches all other modules.

Supported file types

  • Pipeline CSV: weekly opportunity snapshot from SAP CRM/Sales Cloud export.
  • VAT CSV: value at target data for the period.
  • Melody CSV: presales activity export from Melody/Databricks.
  • Targets CSV: SA and team targets for the current period.

How to upload

  • Go to the ETL module in the top nav.
  • Select the file type from the dropdown.
  • Drag and drop the file or click to browse.
  • Click Process — the app validates and loads the data into HANA.
  • A success/error summary is shown after processing.
Important: Always upload files in the expected format. If columns are renamed or missing, the ingestion will fail with a validation error.
🤝
Deal Qualification Structured sessions · MEDDIC · complex opportunities
▼

Overview

Provides a structured framework for qualifying complex deals. Used in alignment sessions between SA, AE, and management.

Key features

  • Session creation: create a qualification session tied to a specific opportunity.
  • Qualification dimensions: covers economic buyer, decision criteria, decision process, identified pain, champion, and competition.
  • Notes & scoring: add free-text notes per dimension and track a qualification score over time.
  • History: view previous sessions for the same account to track evolution.
Tip: Run a qualification session before deal reviews or before requesting executive sponsorship to ensure alignment on deal health.
⚙️
Admin Panel Admin only Users · roles · permissions
▼

Overview

User and permission management for the application. Only accessible to users with the Admin role.

Key features

  • User list: see all registered users, their role, and last login date.
  • Role assignment: promote a user to Admin or restrict to SA — takes effect on their next page load.
  • Module permissions: enable or disable specific modules per user if finer-grained control is needed.
  • Deactivate user: removes access without deleting the account history.
Security note: Admin access should be limited to the project owner and designated ops contacts. Do not share admin credentials.
